# feat: OpenRouter as a second transcription provider, beside Gemini          ✅ COMPLETED — 2026-09-19 (Phase 4 post-merge)

## Problem

[#33](https://github.com/mhmzdev/whatsapp-agent-cli/issues/33). Transcription is Gemini only (`PROVIDERS = ("gemini",)`, `wa_agent/transcribe.py:29`). Hisab transcribes through OpenRouter by default, so its migration onto `wa-agent` ([hisab-whatsapp#57](https://github.com/mhmzdev/hisab-whatsapp/issues/57)) must either keep its own transcription module or move every self-hoster to Gemini. With OpenRouter here, Hisab deletes `hisab/transcribe.py`.

Policy, settled and not reopened: **Gemini and OpenRouter only, nothing else, and no OpenAI provider, endpoint or key name anywhere in the package** (an OpenRouter model id that starts with `openai/` is none of those). The provider stays explicit: default `gemini`, never inferred from which key is set.

## Approach

**One request builder per provider inside `transcribe.py`, one shared failure mapping.** `transcribe()` keeps its shape and its guards (provider known, file exists, audio extension known, key present), then hands off to `_gemini_request` or `_openrouter_request`. Both return a response that goes through the same status mapping: a retryable status or a transport error is `transcription_unavailable` (13), any other non-2xx is `transcription_failed` (14), and each provider has its own `_text_of` that turns a body into text or raises 14. An empty transcript is a failure for both.

**The OpenRouter request mirrors what Hisab already does in production** (`hisab/transcribe.py`, read for its shape only, not imported): `POST https://openrouter.ai/api/v1/audio/transcriptions`, `Authorization: Bearer <key>`, multipart with form field `model`, optional `language`, and the file as `file=(name, bytes)`; the reply is `{"text": "…"}`. Three details are deliberate:
- The file goes as bytes, not an open handle, so nothing is left open on a failure (the Gemini path already reads bytes).
- No mime type is attached to the file part, exactly as Hisab does: the extension carries the format.
- `language` is passed through as given. Whisper-style endpoints expect a code such as `ur`, not the word `urdu` the Gemini prompt takes, and this package cannot know which the provider wants without a live call; the `--language` help says so.

**Keys and models resolve per provider, from one table each.** `KEY_ENVS = {"gemini": "GEMINI_API_KEY", "openrouter": "OPENROUTER_API_KEY"}` and `MODELS = {"gemini": "gemini-2.5-flash", "openrouter": "openai/whisper-1"}`. The OpenRouter default `openai/whisper-1` is the id every OpenRouter config Hisab ships sets (OpenRouter ids are namespaced; the bare `openai/whisper-1` is only a fallback in Hisab's code), kept so the migration changes nothing. It is an OpenRouter model id, not a provider, endpoint or key name, and it lives in the `MODELS` constant only: the README never advertises it and says only that `--model` takes an OpenRouter model id. `--key-env` and `--model` still override either provider. The provider is never chosen by looking at which variable is set: with `GEMINI_API_KEY` and `OPENROUTER_API_KEY` both exported, no `--provider` means Gemini; with only `OPENROUTER_API_KEY` set and no `--provider`, the run fails with `no_transcription_key` naming `GEMINI_API_KEY`.

**Library compatibility (hisab#57 builds against 0.1.0 as it stands).** Every existing name, argument and return keeps working: `transcribe()` still returns a `str` and raises coded `WhatsAppError`s; `DEFAULT_MODEL`, `DEFAULT_KEY_ENV`, `GEMINI_URL`, `PROMPT`, `api_key()` and `mime_for()` stay. One default changes representation: `key_env=DEFAULT_KEY_ENV` becomes `key_env=None`, meaning "this provider's own variable". For a caller who passes nothing (Gemini) the value read is the same `GEMINI_API_KEY` as today. `recv --json` output and the message shape are untouched; `recv --transcribe` only gains an option.

**`no_transcription_key` goes provider-neutral.** The fixed message becomes `no transcription key found; the detail line names the variable to set, or pass --key-env NAME`, with exit status 12 unchanged. The `detail:` line names the variable actually read, so `error [no_transcription_key]: …` is followed by `detail: OPENROUTER_API_KEY is not set`. `docs/errors.md`'s row follows, and `recv --transcribe`'s one-line up-front warning already prints the variable name, so it now prints the chosen provider's.

**`recv --transcribe` gains `--provider`** (default `gemini`, same free-text option as `transcribe`), validated up front: an unknown provider fails before the first poll with `bad_usage`, rather than marking every voice note `transcription_error: bad_usage` for the rest of a `--follow`. The existing `--transcribe-model` and `--key-env` apply to whichever provider is chosen.

**Invariants kept.** Secrets only from the environment; the key is never printed, never in a URL, and no message or detail carries it. Voice notes are transcribed before the agent sees them and a failed transcription is reported, never handed on as speech (an empty or missing `text` is 14). Audio is never kept: the existing temp-dir handling in `_transcribe_into` is unchanged. Privacy: fixtures use made-up keys and a fake audio file; the docs name no personal setup.

## Risks
- **The OpenRouter endpoint shape is unconfirmed against the live platform.** It is copied from what Hisab does in production, but this lane makes no live call. Mitigated by keeping the url, the default model and the `language` handling in named constants and one help string, and by Phase 4. Until Phase 4 is done the PR body says the request is pinned by a fake-session test and not yet confirmed live.
- **`openai/whisper-1` may not be the id OpenRouter's endpoint takes.** It is Hisab's production default, so it is the safest guess; if it is wrong the failure is a clean 14 with the provider's own words in `detail`, and the fix is one constant.
- **`language` semantics differ between providers** (a name in the Gemini prompt, a code for a Whisper-style endpoint). Passed through as given and documented in the help text rather than translated by a table this package would have to maintain.
- **Changing `key_env`'s default from `"GEMINI_API_KEY"` to `None`** is the one visible signature change. It is behaviourally identical for every caller who does not pass an OpenRouter provider, and hisab#57 is written against Gemini-or-nothing today; the lead should confirm nothing there passes `key_env` positionally (it is keyword-only).
- **`recv --transcribe --provider` up-front validation** adds a new early exit to `recv`. It only triggers with `--transcribe` and an unknown provider, which was previously a silent per-message failure.

## Out of scope
- Any provider beyond Gemini and OpenRouter, in particular anything OpenAI: no provider, endpoint or key name (the check enforces it).
- A configurable OpenRouter base url, and any "auto" provider choice: Hisab keeps its own and passes the provider it picked.
- Offline transcription ([#20](https://github.com/mhmzdev/whatsapp-agent-cli/issues/20)).
- A version bump, a promote PR to `main`, or a `CHANGELOG.md` entry: releases are the owner's call.
- Any live call from this lane. Changing `recv --json`, or the return shape or names of `poll`, `send_iter`, `download`, `Store`, `WhatsApp`.
